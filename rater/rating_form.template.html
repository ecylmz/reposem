Declared commit labels

Each row is the subject line of a commit that a project lists in its .git-blame-ignore-revs file. Pick the one category that best describes what the commit does. Judge from the subject line and repository name only; when two categories fit, choose the one that names the main change. Your answers save automatically.

Category definitions
Formatter
An automatic code formatter was run (Black, Prettier, clang-format, rustfmt, scalafmt, pgindent, RuboCop autocorrect and similar), or its configuration was applied to the code.
Whitespace
Only whitespace, indentation, tabs, line endings, or trailing spaces change, without naming a formatter.
Lint or spelling
Fixes for linter or static-analysis warnings (flake8, cppcheck, clang-tidy, pyupgrade), typos, or spelling.
Style
Manual style or cleanup changes that are not a formatter run: braces, quotes, import order, naming conventions, coding-standard fixes.
Migration
Conversion to another language, syntax, or API version: Java to Kotlin, Python 2 to 3, new namespace syntax, modernized idioms.
Move or rename
Files, directories, or code elements are moved, renamed, split, or reorganized.
License or header
License texts, copyright notices, or file headers are added or updated.
Refactoring
Structural code changes that keep behavior: replacing helpers, extracting functions, adding type annotations.
Other
Anything else, including merges and subjects that give no clue.
